# anki-pipeline: текущее состояние и дальнейшее развитие

Дата фиксации: 19 июля 2026 года.

## Цель проекта

Полностью локальный конвейер, который превращает учебное видео в качественные
Anki-карточки. Облачные и платные API не используются. Текущая конфигурация:
Windows, NVIDIA RTX 3060 Ti 8 GB, Ollama и `faster-whisper`.

## Текущее состояние

Реализован текстовый конвейер:

```text
video
  -> audio.wav
  -> transcript.json
  -> semantic_segments.json
  -> knowledge_items.json
  -> knowledge_review.json
  -> target_expressions.json
  -> card_candidates.json
  -> card_media.json + media/*.jpg
```

Работают следующие возможности:

- извлечение mono-аудио 16 kHz через FFmpeg;
- транскрибация `faster-whisper` с таймкодами и прогрессом;
- CUDA `float16`, автоматический CPU fallback;
- локальная смысловая сегментация через HTTP API Ollama;
- извлечение атомарных знаний и отдельная проверка их качества;
- генерация текстовых кандидатов карточек;
- извлечение слов, грамматических конструкций и полных предложений изучаемого языка;
- хранение оригинального написания, чтения, романизации и перевода отдельно от
  исходного транскрипта;
- статусы `verified` и `needs_review` для языкового материала;
- локальные глоссарии `glossaries/<language>.json`;
- замена подтверждённой романизации оригинальным написанием в `front` и `back`;
- повторное использование результатов и точечная перезапись через `--force`;
- атомарная запись итоговых JSON и диагностические файлы при ошибках Ollama.
- локальный выбор кадров через FFmpeg, Pillow и NumPy без OCR и vision-моделей;
  отсутствие подходящего кадра хранится как `image: null`.

Текущая модель Ollama: `qwen3:8b`. Модель Whisper по умолчанию: `small`.

На контрольном японском видео текущий результат содержит 54 языковых объекта:
17 терминов, 17 грамматических конструкций и 20 предложений. Автоматически в
карточки допускаются только подтверждённые выражения. Последний тестовый прогон:
94 теста успешно.

## Команды текущего полного цикла

```cmd
py -m src.pipeline "input/video.mkv" --language en --device cuda --semantic-segment
py -m src.pipeline "input/video.mkv" --extract-knowledge
py -m src.pipeline "input/video.mkv" --review-knowledge
py -m src.pipeline "input/video.mkv" --extract-target-expressions --target-language ja
py -m src.pipeline "input/video.mkv" --generate-card-candidates
py -m src.pipeline "input/video.mkv" --extract-card-images
py -m src.pipeline "input/video.mkv" --build-anki-deck
```

Единого флага для полного цикла пока нет. Его стоит добавить после стабилизации
двух оставшихся этапов, чтобы одна команда могла безопасно продолжать работу с
последнего готового результата.

## Контракты данных

Каждый этап читает готовый JSON предыдущего этапа и не должен запускать дорогие
предыдущие операции повторно.

- `transcript.json` — неизменяемая транскрипция речи и исходные таймкоды.
- `semantic_segments.json` — смысловые блоки без потери transcript segment IDs.
- `knowledge_items.json` — атомарные учебные тезисы с источниками.
- `knowledge_review.json` — решения keep, discard, merge и split.
- `target_expressions.json` — отдельный языковой слой. Содержит `term`,
  `grammar_pattern` и `example_sentence`.
- `card_candidates.json` — проверенные текстовые кандидаты, но ещё не готовая
  колода Anki.

Связи между файлами должны храниться через ID, а не через копирование и
последующее угадывание текста.

## Известные ограничения

- В контрольном видео нет встроенных субтитров, а основная речь английская.
  Whisper иногда искажает японскую романизацию (`ashita` -> `ashto`).
- Ollama может правдоподобно восстановить японское предложение неправильно.
  Поэтому непроверенные формы остаются `needs_review` и не попадают в карточки.
- Романизация может оставаться в английском пояснении, если для неё нет
  подтверждённой записи в локальном глоссарии.
- `card_candidates.json` пока не является `.apkg` и не импортируется в Anki.
- Изображения из видео пока не извлекаются.
- Git remote не настроен, поэтому локальные коммиты создать можно, а push — нет.

## Этап 1: изображения из видео — базовый media layer реализован

Цель: подобрать для карточки один полезный кадр или отказаться от изображения,
если оно не добавляет учебной ценности.

Рекомендуемый поток:

```text
card candidate
  -> source transcript segment IDs
  -> временной диапазон
  -> несколько кадров-кандидатов через FFmpeg
  -> локальная оценка кадров
  -> выбранный image asset или null
```

Реализовано:

1. Добавлен `src/frame_extraction.py` для вызова FFmpeg через `subprocess` и
   работы с путями через `pathlib`.
2. Временной диапазон вычисляется только из `source_transcript_segment_ids`.
3. Берётся несколько кадров внутри диапазона, а не один кадр по его началу.
4. Почти одинаковые, полностью чёрные и размытые кадры отбрасываются локальными
   метриками. Не отправлять изображения во внешние сервисы.
5. Тяжёлая vision-модель и OCR не добавлены. MVP оценивает техническое качество,
   но не понимает содержимое слайда и не отличает его от говорящей головы.
6. Выбранные изображения сохраняются в
   `output/<video>/media/<stable_name>.jpg`.
7. `card_media.json` связывает `card_id`, временную позицию,
   относительный путь, способ выбора и оценку качества.
8. Добавлены флаги:

```text
--extract-card-images
--frames-per-card 5
--image-policy auto|always|never
--force
```

Критерии готовности:

- этап не перезапускает транскрипцию или Ollama;
- имена файлов стабильны при повторном запуске;
- отсутствующие подходящие кадры представлены как `image: null`;
- все пути относительные и переносимы вместе с будущей колодой;
- есть тесты выбора таймкодов, дедупликации кадров и поведения без изображения;
- существующие JSON не повреждаются при ошибке FFmpeg.

## Этап 2: формирование карточек Anki — реализован

Цель: превратить проверенные `card_candidates.json`, `target_expressions.json`
и `card_media.json` в импортируемый результат.

Продуктово простой первый вариант — генерировать `.apkg` напрямую локально с
помощью `genanki`. AnkiConnect на этом этапе не нужен: `.apkg` проще проверить,
перенести и импортировать, а запущенный Anki не требуется.

Реализовано:

1. Добавлены отдельная модель итоговой карточки и валидаторы входных данных.
2. Стабильный GUID формируется из источника и `card_id`, поэтому повторный экспорт
   не создавал дубликаты.
3. Созданы поля заметки:

```text
Front
Back
Extra
TargetText
Reading
Romanization
Image
Source
StartSeconds
Tags
```

4. Добавлен минимальный читаемый шаблон без сложного CSS. Японские символы
   использовать системный fallback-шрифт и корректный UTF-8.
5. Изображение добавляется только при наличии выбранного media asset.
6. Медиа собираются внутрь `.apkg` с уникальными стабильными именами.
7. Результат сохраняется как `output/<video>/<video>.apkg`.
8. Дополнительно сохраняется `anki_export_manifest.json` с GUID, card ID,
   knowledge IDs, expression IDs и media paths для диагностики.
9. Добавлен CLI-флаг:

```text
--build-anki-deck
```

Критерии готовности:

- `.apkg` успешно импортируется в настольный Anki;
- японский текст, чтение и изображения отображаются корректно;
- повторная сборка даёт стабильные GUID;
- discard и `needs_review` не попадают в колоду автоматически;
- отсутствующее изображение не ломает шаблон;
- экспорт работает полностью локально;
- структура `.apkg` и manifest проверяются автоматическими тестами.

## После двух этапов: браузерный GUI

GUI следует делать только после стабилизации файловых контрактов и сборки
реальной `.apkg`. Интерфейс должен быть тонким слоем над существующим pipeline,
а не второй реализацией бизнес-логики.

Минимальный GUI:

- выбор видео и языка;
- запуск полного цикла и прогресс каждого этапа;
- продолжение после ошибки или остановки;
- просмотр транскрипта и таймкодов;
- проверка `needs_review` выражений;
- предпросмотр и редактирование карточек;
- выбор другого кадра из подготовленных кандидатов;
- исключение карточки;
- кнопка сборки `.apkg` и ссылка на готовый файл.

Для локального браузерного интерфейса достаточно небольшого backend-приложения.
До выбора фреймворка нужно завершить два этапа выше; иначе GUI начнёт диктовать
нестабильную структуру данных и усложнит дальнейшую переработку.

## Рекомендуемый ближайший шаг

Проверить собранную `.apkg` на реальном видео импортом в настольный Anki. После
стабилизации реального импорта можно делать тонкий браузерный GUI над готовыми
файловыми контрактами, не дублируя бизнес-логику pipeline.
