# Добавление синтетического аудио в карточку

Дата проверки: 18 октября 2026 года.

Синтетическое аудио уже реализовано. Приложение создаёт MP3 японским голосом Nanami, сохраняет его в проекте и прикрепляет к карточке Anki. Синтез включается автоматически, если поиск готовой записи не дал результата или завершился ошибкой.

## 1. Запуск из интерфейса

В интерфейсе есть два варианта:

- **Кнопка «Добавить аудио» внутри карточки** сохраняет её правки и добавляет аудио только к ней. Кнопка позволяет заменить существующую запись.
- **Общая кнопка «Добавить аудио»** обрабатывает включённые карточки с заполненным текстом для аудио, у которых нет актуальной записи. Перед запуском нужно сохранить правки карточек.

Массовое добавление сохраняет актуальные записи, включая загруженные вручную. Одновременно обрабатываются до четырёх карточек. Результат показывает число добавленных записей, карточек без аудио и ошибок.

Реализация: [src/gui/routes.py](src/gui/routes.py), [src/gui/templates/review.html](src/gui/templates/review.html).

## 2. Подготовка текста

При создании карточки приложение сначала ищет японский текст в ответе, затем в вопросе. Из первого подходящего поля выбирает самый длинный японский фрагмент. Текст и чтение можно изменить вручную.

Например, из `関[かん]する` подготавливаются:

| Поле | Значение | Назначение |
|---|---|---|
| Текст для аудио | `関する` | Поиск записи и синтез речи |
| Чтение | `かんする` | Поиск словарной записи |

**Поле «Чтение» не управляет произношением Nanami.** Синтезатор получает только поле «Текст для аудио», очищенное от фуриганы. Поэтому исправление чтения само по себе не исправит произношение синтетического голоса.

При обычном редактировании вопроса или ответа поля аудио не пересчитываются автоматически: обработчик сохраняет переданные значения этих полей.

Реализация: [src/card_input.py](src/card_input.py), [src/audio_sources.py](src/audio_sources.py), [src/audio_tts.py](src/audio_tts.py).

## 3. Выбор источника

Функция `find_or_generate_audio` выполняет следующие действия:

1. Ищет словарную запись в JapanesePod101. Для поиска нужны текст и чтение. Текст длиннее 40 символов пропускается.
2. Если записи нет, ищет её в Wikimedia Commons. Для текста длиннее восьми японских символов этот источник пропускается. Из Commons принимаются записи с подходящим описанием и открытой лицензией.
3. Если готовой записи нет или поиск завершился обрабатываемой ошибкой, запускает синтез.

Отдельного режима «Только синтез» в интерфейсе нет. При замене существующего аудио приложение тоже сначала ищет готовую запись.

Реализация: [src/audio_sources.py](src/audio_sources.py), [src/audio_tts.py](src/audio_tts.py).

## 4. Создание синтетической озвучки

Приложение использует библиотеку `edge-tts` и голос `ja-JP-NanamiNeural`.

Последовательность работы:

1. Удаляет фуригану из текста. Если текст пустой, возвращает отсутствие результата.
2. Передаёт текст в `edge_tts.Communicate(text, VOICE)`.
3. Принимает поток ответа и объединяет только фрагменты типа `audio`. Служебные события игнорируются.
4. Возвращает аудиоданные с расширением `.mp3` и источником «Синтез речи · Nanami».

| Параметр | Текущее поведение |
|---|---|
| Голос | Nanami, японский |
| Скорость, высота и громкость | Код не задаёт дополнительные настройки |
| Время ожидания синтеза | До 60 секунд |
| Максимальный размер | 10 МБ |
| Пустой ответ сервиса | Ошибка, файл не прикрепляется |
| Ошибка соединения | Сообщение с предложением проверить интернет и повторить попытку |
| Автоматический повтор синтеза | В коде приложения не предусмотрен |

Синтез требует интернета: текст для аудио отправляется сервису Microsoft. README описывает подключение как неофициальное, без оплаты и ключа API. Доступность сервиса при этой проверке не проверялась.

Реализация: [src/audio_tts.py](src/audio_tts.py), [requirements.txt](requirements.txt), [README.md](README.md).

## 5. Сохранение и привязка к карточке

Файл сохраняется по пути:

```text
output/<проект>/media/<ID карточки>.mp3
```

Сначала приложение записывает временный файл, затем заменяет им целевой. В `project.json` сохраняются:

| Поле | Содержимое |
|---|---|
| `path` | Относительный путь к файлу |
| `text` | Текст, для которого добавлена запись |
| `reading` | Чтение на момент добавления |
| `source` | «Синтез речи · Nanami» |
| `source_url` | Ссылка на проект edge-tts |
| `license` | Для синтеза — пустая строка |
| `attribution` | `Microsoft Edge · Nanami` |

Перед прикреплением приложение повторно проверяет текст и чтение карточки. Если пользователь изменил их за время запроса, результат не прикрепляется. После успешного сохранения запись можно прослушать в интерфейсе.

Реализация: [src/project_store.py](src/project_store.py).

## 6. Актуальность записи

Приложение сравнивает текущие `audio_text` и `audio_reading` со значениями, сохранёнными вместе с аудио.

Если текст или чтение изменились:

- интерфейс предлагает обновить запись;
- массовое добавление снова включает карточку в обработку;
- экспорт и отправка через AnkiConnect не прикрепляют устаревшее аудио.

Даже изменение только чтения делает запись устаревшей, хотя при синтезе Nanami это поле не используется.

Реализация: [src/gui/routes.py](src/gui/routes.py), [src/gui/templates/review.html](src/gui/templates/review.html), [src/anki_export.py](src/anki_export.py).

## 7. Передача в Anki

Оба пути используют общую подготовку карточки в `prepare_card`:

- **Экспорт `.apkg`:** аудиофайл включается в пакет колоды.
- **AnkiConnect:** аудиофайл кодируется в Base64 и передаётся в медиатеку Anki через `storeMediaFile`.

Поле `Audio` получает значение вида:

```text
[sound:anki_audio_<дата>_<хеш>.mp3]
```

Имя содержит дату и хеш проекта, карточки и содержимого файла. Это предотвращает замену аудио одноимёнными файлами других карточек.

Шаблон выводит поле `Audio` на стороне ответа. Сам файл передаётся в Anki, поэтому для его воспроизведения после импорта повторный синтез не нужен.

Реализация: [src/anki_export.py](src/anki_export.py), [src/anki_connect.py](src/anki_connect.py).

## 8. Проверка реализации

18 октября 2026 года выполнены тесты следующих модулей:

- `tests/test_audio_tts.py`;
- `tests/test_audio_sources.py`;
- `tests/test_gui.py`;
- `tests/test_anki_export.py`;
- `tests/test_anki_connect.py`.

**Результат: 61 тест прошёл.** Проверяются переход к синтезу, обработка аудиофрагментов, удаление фуриганы, ошибки, добавление к карточке, защита от изменения текста во время запроса, экспорт и отправка в Anki.

Первый запуск столкнулся с запретом доступа к стандартной временной папке Windows. Повторный запуск с временной папкой внутри `output` прошёл. Осталось предупреждение о невозможности записать кеш pytest, которое не помешало тестам.

Тесты синтеза подменяют внешний сервис. Они подтверждают работу кода, но не текущую доступность Microsoft и не качество японского произношения.

Исходный код приложения при подготовке отчёта не изменялся.
